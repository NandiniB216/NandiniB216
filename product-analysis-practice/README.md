# Guided Wellness Session Planner — Product Analysis Practice

**An independent, fictional product-analysis case study.** This is a documentation and prototype-planning exercise created from scratch for portfolio practice. It is not an HCL Healthcare product, not Habit In Motion, and does not contain employer code, data, screenshots, requirements or internal information.

## The problem

A fictional wellness platform wants to help adults choose and complete short guided movement sessions at home or at a desk. The current experience is assumed to be fragmented: users cannot easily tell which session suits their available space, what to expect, or whether they completed a session.

This is a proposed problem scenario, not user research or a claim about a real product.

## What this case study demonstrates

- Problem framing and assumptions
- User journey and simple process mapping
- Functional requirements and business rules
- Acceptance criteria in Given/When/Then format
- Edge cases and basic accessibility/privacy considerations
- UAT test design
- Product-event and KPI definitions
- Clear separation between proposed behaviour and verified implementation

## Scope

This is a **BA/product documentation case study**, not a deployed application. No camera, pose tracking, rep counting, clinical recommendation or health outcome is implemented or validated here. All personas, scenarios, rules and targets are illustrative assumptions.

## How I approached it

I started with a user problem, identified assumptions that would need validation, mapped the journey, wrote testable requirements, and defined what evidence would be needed before claiming success. The aim is to show how I structure product problems—not to imply that a proposed design has been built or tested with real users.

## AI-use disclosure

AI tools were used to assist with drafting and reviewing this documentation. The scenario is fictional; the requirements and proposed decisions are not presented as employer work or validated user research.

## Next steps if this were a real project

- Interview users and validate the problem
- Review safety and accessibility requirements with qualified stakeholders
- Prototype the flow and run usability tests
- Baseline completion and abandonment measures
- Revise requirements from observed evidence
